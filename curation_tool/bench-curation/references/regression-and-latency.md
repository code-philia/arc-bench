# 例程对照、准备链时延与helper优化回归

适用于用户已提供多个实现、旧需求生成代码或具体超时证据的治理任务；无例程时只做独立分析与真实helper模拟。遵循[主流程](../SKILL.md)的授权和验证选择，不自动搜索应用、启动服务或修改应用。定位器改法见role的[集合身份与查询成本](../../bench-role-curation/references/collection-identity-and-query-cost.md)。本参考不预设技术栈、端口、存储、超时值或评分数量。

## 按最早阻塞归因，允许同一用例逐步暴露不同问题

| 类别 | 依据与处理 |
| --- | --- |
| 旧需求与当前标准不同 | 文案、流程或业务规则确实不同；按当前需求记录迁移，不称为测试泛用性缺陷。应用修改须在授权范围内。 |
| 应用业务缺陷 | 错误对象、权限/持久化、丢正文、取消保存、容量/排序等违反当前需求；保留业务证据，不放宽测试迁就。 |
| 合理实现被拒 | 当前自然语言要求已满足，失败来自未规定的role、结构、动作能力或范围假设；保存最小前后对照，修适配而非强制应用布局。 |
| 证据不足或含义未定 | 记录具体争议、已知行为和阻塞步骤；核实需求，不将所有timeout直接划入同一类别。 |

启动/依赖/准备环境故障单列，不能当业务失败或通过。记录每个失败的最早位置、已完成副作用、未到达的目标步骤。保存成功后可能先被慢locator遮挡，优化后又暴露草稿回填为空、匿名列表缺失或静态记录被动作计数拒绝；这些需要分别判断，不因最初归因是helper便一并归入兼容问题。

## 建立可对照的运行，而不是追求单次绿

任务要求比较多个实现或真实通过率时，修改前记录当前需求/scenario/图片、spec、helper、fixture及执行配置指纹，保留可恢复源码快照；排除依赖和运行产物。已经发生的修改不能冒称原始基线，说明能恢复的起点及缺口。

核实每版实际启动与存储方式；若任务已授权建立实验环境，为每版使用独立端口和存储，并保留原生初始数据定义及实际initial状态。要求的账号等启动环境调整单列，与应用源码修改、业务修复分开。不能触碰其他实验库或通过清库使共享状态断言变容易；测试要求同库重复时保留该规则。

不同技术栈、关系表和存储方式按当前业务关系及行为判断，不以schema或DOM相同作为泛用性要求。已授权修复应用时，围绕具体迁移/缺陷保留合理实现差异，不把多版统一重写成同一实现来获取成绩。跨重启、权限与路由等业务风险按quality的[应用证据边界](../../bench-quality-curation/references/false-acceptance-review.md#应用回归中的证据边界)检查。

每轮记录应用及helper版本、起始存储、运行范围和配置。评分测试/helper的冻结范围及允许修改边界以用户授权为准，不自动扩大。需要诊断变体时另存并明确标记；只在浏览器DOM中补main或改包装的实验，也不等于原实现通过。不要添加测试专用接口、硬编码业务对象或识别测试环境。原始失败与中间版本报告保留，定向成绩和诊断成绩单列。

## 拆解准备链，而非只看timeout文字

先沿实际helper调用链标注创建、保存、重开、回父列表、登录/导航和目标断言。多个UI对象、count/visible/open和再次回查共同消耗同一个测试预算；每次单独不慢也可能累积超时。核实测试总预算、expect预算和既有逐用例覆盖，不把诊断脚本默认预算当评分预算。

| 要回答的问题 | 取证 |
| --- | --- |
| 应用未启动还是业务请求失败？ | 启动日志、进程/健康状态、实际请求及响应；未启动不执行或不计业务评分。 |
| 保存/读取是否已成功？ | 相关请求状态、对象身份、响应内容及后续UI/持久化证据。成功状态码只证明该请求，不证明正文、权限、回填或首页列表正确。 |
| 等待异步结果还是重复解析已唯一的目标？ | trace中的query/count、locator expect和click及其结果、候选范围、重复调用次数；注意已返回1仍可能在下一个复杂查询耗尽预算。 |
| 最终业务断言是否运行？ | 最早失败的helper/REQ步骤和调用栈；未准备完超上限对象时，不追认容量、排序、删除或最终正文检查。 |

401等状态按端点、登录态和需求解释：匿名个人访问记录拒绝可能正常，但需求允许匿名的内容列表被同一认证失败清空，是另一业务问题。不能统一忽略或统一计错。

时间统计区分测试总时长、准备阶段、网络、选择器查询和断言。trace的RPC墙钟时长不是CPU时间；报告统计口径、未完成调用是否漏计，避免把嵌套step与其内部RPC相加造成重复。选择器字符串长度、调用次数只作线索，不能单独证明根因。

## 用有界对照定位成本

在同一或可比页面、相同对象/数据量及相同公共helper动作上测量；已知精确原生locator可作诊断参照，但它缺少owner/唯一性等约束时不能直接替换正式适配器。声明样本数、机器共享负载、浏览器/构建和存储版本，不把少量样本外推固定性能保证。

可用一次只改一个结构因素的独立DOM对照，例如加/撤main边界或移除装饰；必要时A-B-A检查变化是否可逆。它帮助隔离范围推断成本或误拒条件，不代表该结构应成为产品要求，更不是评分成绩。没有对照支持时只报告怀疑，不将所有超时统一归因。定位瓶颈后在公共helper上做一般优化，不能靠应用迎合locator。

## 正确性、成本和评分纪律一起回归

1. 针对明确的慢查询或时序问题修改，先通过真实helper的合理正例、错误归属/重复反例及相关准备链；需要控制渲染切换时用确定性最小检查，不依靠随机sleep取巧。
2. 对照旧局部case的稳定身份、输入、检查内容和预期，确认没有删除、放宽、跳过或漏运行；新增case可能使按累计数量生成的显示名移位，须核实内容及顺序，不能把名称/数量相同当作覆盖不变。新编号或同名case也不能掩盖内容变化。
3. 测量代表性热路径及完整操作成本。更快的集合查询可能被更重的动态候选、删除确认或动作作用域抵消；也可能因为执行加快而暴露旧候选失效。发生新失败时保留该版本，定位实际阶段，再修公共逻辑，不用随意重跑择优。
4. 用户已提供例程且共享逻辑影响广时，最后对修复后的同一版本分别完整运行；不得拼接定向通过或选择不同版本的最好分。未运行、跳过、准备失败及目标断言失败分别报告，分母不因兼容性争议自动缩小。
5. 性能比较保持业务断言、timeout/expect预算、重试、跳过、并发及业务准备规则不变；只按授权分离baseURL、端口和报告路径。确有独立产品性能要求或预算治理任务时另立变更与基线，不能混作helper提速成绩。
6. 结束核对受保护文件与运行版本指纹、旧正反例结果、剩余问题及服务归属；只停止/重置本轮明确建立的资源。比较清单时可以规范化平台路径分隔符，但不能因此忽略文件集合或内容哈希差异。

仅修改skill或文档时，执行主流程的元信息/引用检查及diff复核；不为了填成绩重新启动例程或修改治理状态。共享skill保留这些判断方法，历史分数、具体例程、trace、耗时样本和未解决个案证据留在本地报告。
