# 需求与测试治理主流程

先读仓库`README_curation.md`，确定用户授权的目标需求、参考图、评分测试和允许改动。本仓库已治理BookStack和StackOverflow的需求与测试；未另行指定时沿用会话中已确认的目标，不自动切换或推进其他应用。只检查或更新skill时，不启动实际需求治理。

通用方法与项目约定分开：目标为BookStack时读取[项目适配说明](references/bookstack-profile.md)；其他目标先核实自己的路径、身份数量、数据来源和工具映射，不能直接套用BookStack脚本或写入其状态。例程、历史报告和本地状态都不是使用本流程的前置条件。

## 职责与路由

| 问题 | 负责的子skill | 职责边界 |
| --- | --- | --- |
| 示例、数据来源、随机素材和前置对象依赖 | [data](../bench-data-curation/SKILL.md) | 提供输入/身份/父关系和准备契约；交互适配交role，结果检查交quality |
| 产品交互、文案/结构约束，需求和scenario含义对齐 | [ui](../bench-ui-curation/SKILL.md) | 确定应保留的标准及可兼容差异，不由helper倒推产品要求 |
| 元说明、评测协议、父子重复及文字交付清理 | [meta](../bench-meta-curation/SKILL.md) | 整理自然表述及规则归属，不另行决定产品交互或业务断言 |
| 控件识别、语义接口、替代定位、读写/操作和状态观测 | [role](../bench-role-curation/SKILL.md) | 实现已确定的适配契约，不以能定位代替业务正确性 |
| 前提—动作—结果闭合、误接受、持久化和覆盖缺口 | [quality](../bench-quality-curation/SKILL.md) | 主导反例、应有约束和双向验证；与其他职责协同修复 |

这些是问题类别，不是必须依次完成的五个阶段。当前智能体按依赖读取执行，不因此启动子智能体或后台任务。同一问题确定一个主条目，关联其他职责；共用helper可一次修改，各问题保留独立证据，不重复扫描、重复跑同一检查或建立多份进度账本。

## 执行顺序

1. **共同清点**：通读目标description、Given/When/Then、图例、REQ及实际helper/fixture。形成一次对应清单：身份、输入来源、所属对象、动作、预期结果、当前观测、差距和依据。关键词命中不代替语义判断。
2. **先确定标准**：ui判断业务/产品规则与可兼容差异，data确认可信前提，meta识别协议和重复。质量任务可先复现反例；但含义不清时，先明确现有标准或当前用户决定，再实施约束，不能由helper或例程倒推产品要求。
3. **联合修改**：按业务问题及共享依赖组织需求、scenario、准备、适配和REQ修改。先用最小错误实现/合理替代确定预期，再修公共实现及实际调用。保留需求与评分身份、精确数据和断言强度，不自动新增评分场景。
4. **分层验证**：采用下表，quality核实错误实现拒绝、合理实现通过及结果闭合。未运行/未覆盖能力明确记录，不能用文字同步冒充测试覆盖。
5. **交付与恢复**：汇总每项决定、实际验证范围、剩余差距和最小证据，复核文字、ID、引用、数据归属及差异，再清理交付范围内协议与临时产物。

## 默认无例程；用户提供后可迭代

默认从需求、图例和测试独立审查，以合成DOM或最小状态模拟验证真实helper正反例。不扫描workspace寻找应用，不猜测端口、URL、启动命令或数据库，不把“有可用服务”当作用户已提供例程。

只有用户主动提供或在会话中明确指定例程、应用源码或URL，才进入例程迭代。先核实该对象及服务状态，再运行相关REQ；共享改动广泛或出现新失败时按影响扩大回归。先前授权在会话内有效，无需重复确认，但旧端口/构建不保证仍可用。

例程用于暴露未覆盖结构和业务错误，不用于定义全部合法实现。分别归因适配错误、准备问题、应用不满足和环境失败，补充独立正反例，再核对真实调用。提供例程不等于授权修改应用、清库、注册账号或重建环境；这些动作须已有任务授权。无例程时完成独立治理并报告应用级验证缺口，不停掉可做的工作。

多个实现对照、旧需求迁移或准备链超时时，读取[例程回归与时延取证](references/regression-and-latency.md)。区分需求迁移、应用缺陷、合理实现误拒和证据不足；准备失败会遮挡后续问题，不能只给整个用例一个笼统归因。先处理当前已证实的最早阻塞，再重新观察后续步骤。

## 统一验证与证据

| 变更 | 必要验证 | 应用级验证 |
| --- | --- | --- |
| 仅skill/文档/路径 | 元信息、相关引用、文档与工具能力相符、git diff --check；改可执行工具时检查其行为 | 不启动例程 |
| 仅润色/去重，业务不变 | 解析需求，比较身份、引用、层级、场景和业务含义；说明测试不改的理由 | 不因文字整理重跑 |
| fixture/准备契约 | 类型、当前test素材归属、字段与父关系确实被消费 | 用户已提供例程时按影响验证准备链 |
| 定位/读写/状态或结果断言 | 类型、实际REQ接入、合理替代正例与错误实现反例；状态/保存需完整操作链 | 用户已提供例程时跑相关REQ |
| 共享状态/容量 | 准备超出边界、完整计数、清理仅限本test修改状态 | 已提供例程且需要验证共享状态时同库重复，不清历史取绿 |

结构、类型、素材模拟、合成适配、应用回归是不同证据。逐项记录实际命令、源版本、范围和结果；定向补测不拼成新全量成绩，历史数字不作本轮证据。工具与命令按项目适配说明选取，子skill不再各跑一套流程。

适配正确性和计算成本须分别验证。共享helper优化后比较旧正反例的身份、内容及结果，再验证新反例；不能只比较通过数量。已有例程时按影响跑准备链和相关REQ，共享范围广泛变化后完整回归。保持原断言、预算、重试、跳过、并发及业务准备规则，不以加时、减少准备对象或替换应用布局冒充优化；细则见[例程回归与时延取证](references/regression-and-latency.md)。仅更新skill不因此启动应用或刷新评分成绩。

本skill包的独立元信息/引用检查为`node curation_tool/check_curation_skills.mjs`，不读取应用需求或启动例程；它不证明流程语义正确，仍需人工复核职责、顺序和边界。

## 状态与收尾

所有进度、审计、决定和报告存于`ref/<目标>/`；无本地记录时从当前源码开始，不继承历史完成结论。恢复条目时检查源指纹，变化后按影响失效并重核，不能刷新基线掩盖旧verified。

每项记录依据、修改/保留/延期理由及需求—测试关联。准备/适配已验证与应用业务未通过分开登记。状态工具及产物规则见[状态与产物约定](references/state-and-artifacts.md)。

默认同步修改需求和测试；确需过渡标记且任务允许时才暂存协议。最终移除交付范围内协议及括号并核对业务含义。不能用静态检查冒充业务通过，也不能因无例程而保留已可安全清理的协议。仅完成当前授权范围，不自动提交、推送或推进其他应用。
