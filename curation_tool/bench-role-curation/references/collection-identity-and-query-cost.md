# 集合身份、渲染切换与查询成本

用于集合/标题误拒、记录计数与打开混用、临时范围失效，或复杂locator导致准备链变慢。执行范围和应用入口遵循[主流程](../../bench-curation/SKILL.md)；同名动作归属沿用[作用域方法](action-scope-compatibility.md)，测量与评分纪律见[时延取证](../../bench-curation/references/regression-and-latency.md)。下面是判定与优化思路，不是任意DOM通用选择器。

## 分开证明记录、身份与动作

| 观察 | 可接受证据 | 不能代替它的证据 |
| --- | --- | --- |
| 当前页面/集合标题 | 当前范围的自身标题；允许在具名集合内部 | 记录卡片标题、导航同文、输入回显 |
| 记录出现/次数 | 正确集合与owner内的实际记录，身份精确，合并同一记录的表示 | 仅计打开控件；全页同文计数；把未知非空结构算0 |
| 打开记录 | 属于该记录的真实动作，唯一且能按要求执行 | 静态名称、tabindex、编辑或删除按钮 |
| 其他对象身份 | 可见非空业务标题/caption与该对象交互区域的关系 | 空白span、隐藏图标、明确装饰节点 |

“静态文字不是入口”不能推成“静态记录不存在”。同一记录可以有名称、图标、链接和维护按钮，不应重复计数；两个真正的同类同名记录也不能按文本合并。允许重名时，父对象和可观察身份关系用于归属；同一操作范围内仍无法区分的目标应拒绝，不能以first/nth选一个。只有名称且不足以识别记录边界时，明确支持缺口，不假装已完成完整计数。

## 容器与caption的细粒度兼容

- **集合自身标题**：具名列表卡片中的页面h1可以是页面标题。不要排除该集合的所有后代；同时保留li/tr/实际记录、嵌套子对象卡片及打开控件内标题的排除。两个有效页面标题仍属于歧义。
- **装饰与外部owner**：空白、隐藏、aria-hidden或明确装饰的span不能单独使整条记录被判给其他对象。可见非空的其他对象caption仍应拒绝；“可见”本身不证明身份，需结合区域和交互关系。
- **详情与列表并列**：owner详情和具名集合可在同一内容布局中并列，不强制嵌套、main或Actions标题。有main时不跨所属main补足；侧栏、导航和其他对象子树不能提供缺失集合。无main的扩大范围仍须有owner及正向集合证据。
- **多种组表示**：同一集合被role、aria-label及标题路径命中时可按DOM身份合并、折叠等价外层包装；两个同级集合或混合具名/标题集合不能因选择较小容器而隐藏。
- **文案与值**：明确规定的操作文案遵从当前需求，旧需求文案不是自动别名。允许的标签/名称变体由ui确定；用户输入、对象名、正文和回填值保持精确。

最小正反例成对构造：集合内自身标题/记录内同名标题；装饰span/真实其他对象caption；并列集合/另一个main或侧栏集合；单一组多路径/两个同级组；静态记录计数/静态文字不能打开。不要只验证某个CSS删掉后能绿。

## 同一业务事实的多种呈现

DOM节点数不总等于业务对象数。对已证明属于同一对象的摘要计数与明细计数，可校验两处值一致；不能仅因数值相同就合并，不同对象、相同owner内重复计数、独立明细组及值不一致仍应拒绝。一处与两处呈现相互切换时，轮询内重新确认归属及一致性，不能锁住首次观察到的节点数。

普通列表或布局包装不自动构成另一条业务记录。具名条目可位于无自身正文身份的包装内；具名父记录、具有独立正文的原生记录和回复区域仍是边界。检查单条包装、多条同文、嵌套记录及其他owner，不能只删掉所有祖先排除条件。

独立历史/结果区可能与详情并列。绑定实际触发动作、当前对象上下文、期望保存内容和结果的新变化；无明确身份时，只支持能够证明唯一归属的范围。旧结果原样保留、其他对象、多个未区分对象、重复结果和临时范围切换需分别验证，不因全页只有一块历史就接受。文本变化对照应使用一致的可见文本口径，不能将textContent与innerText的格式差异误判为新结果。

自然指导和状态通知不必位于main。允许新的布局时，仍保留原有合法的独立阅读表示；不要用额外编辑控件等未经原契约规定的前提，破坏旧正例。新增反例若与已确立的合理表示冲突，应记录并纠正新反例的前提，而不是改旧case身份或预期掩盖回退。

## 临时范围失效必须重新选择

导航或保存后的页面可能先显示临时普通标题、旧header或加载容器，随后正式内容替换它。某路径在首次count时唯一，不代表后续断言时仍有效；锁住旧候选再长等，可能永远等不到已经由另一合法路径提供的目标。

保留候选优先级与歧义规则：较早路径有多个匹配时应拒绝，不能跳到较晚单匹配路径。确认候选的过程中若发现其消失或改变，轮询重新执行整个选择过程，而不是只等待旧候选。可在同一轮内复验唯一性；具体确认次数不是通用协议。locator需反映当前DOM，不缓存ElementHandle、首次count或长期范围结果，也不以固定sleep等待“稳定”。

用真实helper构造可重复的渲染切换：在一次观察与确认之间替换普通标题为语义标题及同文侧栏，或移除旧公共导航但留下合法当前入口。既验证正确入口能继续，也验证新出现重复目标/更换owner后拒绝。必要时在独立检查中控制观察时机，恢复临时拦截；不要把测试时序控制代码加入应用或正式业务路径。

## 减少locator重复展开

慢查询不一定是轮询次数多。`smallestContainers`式的“复杂集合排除自身后代”、多role候选与owner/可见性/范围交集可能复制同一段昂贵推断；即使每次返回唯一目标，count、visible、click仍会重新计算。

优先减少表达式和工作量，再考虑跨观察复用。常见可评估的变换：

1. **动作先识别，再取范围交集**：若已有全页候选动作C及已证明的容器S，把每种role都在S内重新构造，改为C与S的后代取交集。仍须保留可见性、owner、动作身份和唯一性；S自身是动作、外部表单关联等情况需另核语义，不能机械替换。
2. **去嵌套与范围交集分离**：同一组的所有后代都受同一边界约束时，可评估先折叠等价组，再与边界交集，避免把完整布局推断再次复制到hasNot中。Playwright相对作用域、XPath祖先/逃逸及shadow边界会影响等价性，不能只凭集合代数断言安全。
3. **已有局部边界的唯一快路径**：最近owner内容边界内已确认恰有一个所属具名集合时，若能证明继续推断更大布局不会改变目标，可直接使用它。没有或多个候选时保留完整推断，不以局部唯一覆盖同一业务范围内的竞争目标；仍检查错误owner、侧栏、跨main、嵌套及同级重复。

不要为提速要求应用增加main、移动标题、删除装饰或统一DOM；也不要删owner/重复约束、挑第一个、识别测试环境或添加测试专用接口。大而“始终实时”的多路径组合也可能重新放大查询成本，不能只验证它功能正确便默认更优。

优化后保留旧合理正例与错误拒绝，增加触发慢路径的布局及渲染切换反例；检查旧case内容与身份，不仅比较总数。无main、深层包装、并列组、混合别名、重复条目、装饰干扰和更多记录按实际受影响范围选择，不要求每次穷举所有组合。性能与正确性都通过后，再进入主流程调度的应用回归；此参考不承诺固定毫秒数或任意DOM兼容。
