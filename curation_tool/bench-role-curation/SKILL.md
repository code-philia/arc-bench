# 控件语义与适配治理

按[主流程](../bench-curation/SKILL.md)确定目标和契约。ui负责产品/交互标准，role负责实现允许的替代路径，quality负责完整业务断言；验证和状态调度由主流程统一处理。不默认存在例程，项目实现入口由项目适配说明确定。

## 清点与迁移

检查需求中的role/ARIA协议及tests/helpers/support里的定位、读取、填写、操作和状态检查。保留自然“按钮/链接/标题/列表”、键盘可用及业务结果；ARIA可作可选证据，不反过来成为未经规定的产品要求。

按业务用途分类，建立需求/场景ID—实际调用—公共接口—支持/拒绝边界的映射。区分有接口、真实调用已接入、完整正反例已验证；扫描或导入计数都不能证明迁移完成。

| 语义类别 | 适配契约 |
| --- | --- |
| 操作/导航 | 用途、可见、业务范围、唯一、可执行及所需键盘操作 |
| 集合/条目 | 精确对象身份、owner、出现次数、缺失和打开 |
| 字段/复合编辑器 | 原生/自定义实现的填写、读取、清空、回填一致 |
| 标题/正文 | 当前对象详情/阅读区域，排除列表caption、导航和输入回显 |
| 状态 | 可读状态、幂等设置、未知状态拒绝；持久化效果交quality |

沿用或建立目标项目的公共语义接口，让评分REQ表达业务动作而非散布原始Locator操作。复合helper可构造定位器，控件读写和状态处理仍经统一适配。接口名称不必与BookStack相同；具体导出见项目适配说明。

## 范围与替代路径

新增实现先识别用途和控件类型，再选择操作。role不同不代表可无条件互换；静态文字不是打开入口，tabindex不证明动作有效，未知状态不能当false。字段写/读/清空与别名/owner约束须覆盖所有分支。

同名操作审查“用途—所属对象/表单—动作”，不能等例程失败才发现全页定位过宽。遇到此类任务读取[作用域兼容与few-shot](references/action-scope-compatibility.md)：合理无main/无Actions标题/无显式role布局应可支持，Actions、共同祖先或全页唯一均不能单独证明归属；不以first/nth、较小容器或切换路径掩盖业务歧义。

对象身份和用户值保持精确；别名/界面大小写尺度由ui确定，不做全局模糊匹配。对于无可观察交互证据、自定义编辑器或状态无法读取等未覆盖情况，记录支持边界，不声称任意DOM兼容。

## 返回主流程

返回各实际调用的迁移结果及适配边界。按quality需要补充真实helper上的合理替代和错误实现反例，覆盖读写、清空、owner、重复、静态文本、状态未知及完整操作链。仅用户提供例程后按主流程进入应用迭代；定位失败仍需区分准备、适配和业务失败，不自动改应用。
