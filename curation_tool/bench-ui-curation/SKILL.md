# BookStack UI约束治理

## 恢复与边界

仅治理BookStack任务5。现有改造已落地，不因首次使用本skill重复执行；40组合成检查、25/10真实回归是已归档验证范围，不是本次自动运行的结果。历史69处隔离内容已授权清理，当前0处；新增UI改造不得恢复旧评测协议。创建/检查skill本身不重跑治理。日期和时钟、数据准备、role实现协议及最后的断言质量各归对应阶段；不新增评分场景，不自动修改验证case。

## 先判断约束的用途

通读全部description.text及Given/When/Then，结合父子需求、相关测试/helper和参考图逐项分类。定位到需求/场景/步骤ID及字段，记录原文、业务目的、实际测试依赖、处理决定和中文理由；关键词命中不等于应删除。

| 类型 | 决定 |
| --- | --- |
| 业务规则：唯一对象、键盘可操作、持久化、归属、输入输出一致、容量上限 | 保留，不因包含数字或精确值而放宽。 |
| 产品设计：明确导航、保存/取消文案、布局、收藏状态切换 | 保留；参考图提供设计依据，但不能仅凭一种截图推导唯一合法实现。 |
| 仅方便定位/解析：强制placeholder、条目完整可访问名称、容器标签 | 改成自然用途与可观察行为，同步适配测试。 |
| 依据不清或改动会改变产品交互 | 先保留并记录待核实点，不将所有文案泛化。 |

已确认的本案例尺度：页面标题/正文不绑定长placeholder；列表按精确对象身份识别，允许Open/View/Read包装和明确卡片入口；New Book/Create New Book均有参考依据。Favorite/Unfavorite文字切换保留，不顺手扩为图标状态。该有限别名集合不是其他页面必须使用的文案规范。

## 分批修改与适配

按字段/编辑器、操作/导航、集合/条目、状态/展示组织共享改动；先确定业务含义再改公共接口及关联REQ。保留需求身份、自然示例、业务前提和结果；去掉UI精确协议时同步检查场景文本，不能只改description。

- 沿用helpers导出的语义接口；页面编辑使用pageEditor，字段识别、写入、读取、清空与回填断言必须成套兼容。多个标签或别名命中不同字段时失败，不选择第一个。
- 操作别名要有产品/业务依据，并检查实际操作结果；不能用任意包含文本匹配接受近似动作。
- 对象名保持精确、动态值转义正则。条目允许名称包装，但静态文字、Edit/Delete或另一个对象不能成为打开入口；独立通用打开按钮必须绑定到明确对象卡片/行。
- 集合识别按业务范围和owner约束所有分支；同名集合不能跨父对象补足。排除导航/面包屑，覆盖页面切换时旧DOM短暂存在的情况。
- 保留业务断言强度。不用整页搜索、DOM顺序或`.first()`掩盖歧义，不将精确输入值改成任意非空，不为通过case改变业务结果。

## 分层验证与返回

修改前后解析YAML，核对层级、需求/场景/步骤/图片ID、引用、测试身份及原有标记文本/次数。按主skill验证选择表选取受影响检查，以下不是每次必跑清单：

```powershell
npm.cmd run check:bookstack
node curation_tool/check_bookstack_role_compatibility.mjs
node curation_tool/check_bookstack_preparation.mjs
```

上列为Windows命令；非Windows可使用npm。适配脚本使用bench根目录Playwright，运行前核实依赖与Chromium。按需扩展已有检查，不复制另一套适配器。

每项放宽都需要合理替代通过，以及错误实现失败：字段歧义、相似/同名对象、错误owner、静态文字、编辑/删除动作、不可读状态、导航过渡等。用真实helper做代表性合成DOM检查；模拟素材归属不等于UI行为验证。

有可用case时核实URL及服务，运行相关REQ；共享接口影响广泛时做全量回归。比较失败身份和失败阶段，不只比较通过数：本案例New Book入口已解除，但保存后导航仍与需求不符。区分适配、case功能/数据、环境和后置任务，保留最小证据；未经当前授权不修case，不以历史25/10代替本次结果。

通过主skill的state.py在ui阶段登记真实里程碑与检查范围。preserved保留产品决定，deferred明确后置归属，相关浏览器业务仍失败的条目保持blocked；其他已验证的适配范围独立记录。partial不等于全部失败属于适配层，complete也不能由单一case全绿替代完整分类和反例验证。

将分类理由、保留设计、实际别名/结构支持、验证范围和失败最小证据汇总到ui_governance及ref/中的本地进度，逐项进度以workflow_state为准。按主skill[状态与产物约定](../bench-curation/references/state-and-artifacts.md)汇总后清理本轮临时inventory、运行JSON、截图/trace等，不额外堆积永久报告。
