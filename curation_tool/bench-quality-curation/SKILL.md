# 断言质量与误接受审计

按[主流程](../bench-curation/SKILL.md)确定目标和授权。以需求和已确定的产品标准为依据，data提供素材/准备契约，role实现语义适配，ui明确业务缺项及scenario同步，meta整理语言。主流程统一调度验证和状态，quality不是固定最后才开始的阶段。

## 对应与不变量

审查“description—scenario—REQ—真实helper/适配路径”，不以接口存在或已导入证明断言执行。每项标出可信前提、动作用途/owner、同一份输入、应有结果、观测边界和覆盖差距。

| 关注点 | 质量要求 |
| --- | --- |
| 保存/编辑/取消 | 回读输入，编辑前后及取消后核对原/新值，按需求重开或刷新；不让创建副本、只存标题等错误替代原业务 |
| 集合/正文归属 | 全部替代路径绑定当前对象，排除其他对象、列表caption、导航、侧栏和编辑回显 |
| 容量 | 当前test准备超过上限的数据，合并完整记录并去重；未知非空结构不当作0，不能只检查一个新目标出现 |
| 交互及状态 | 定位/可见/焦点不代替正确操作；键盘能力实际操作，状态未知不当false |
| 共享状态 | 当前test随机身份和明确初态；不假定数据库为空，仅恢复本test改变的状态，保留原错及清理失败 |
| 准备契约 | 关联字段真正消费，或在副作用前明确拒绝；资料包含父名不代表已建立关系 |

固定账号、容量数值、支持类型和已知准备限制由项目适配说明及当前源码核实，不把某次应用结果写成通用规则。

## 逐项反例与修复

此类任务读取[误接受审计与few-shot](references/false-acceptance-review.md)。先用最小错误实现反查当前断言；归因后逐项修适配、准备或结果约束，并核对真实REQ接入。错误实现必须拒绝，合理替代仍可通过；不为拒绝反例强制role或布局，也不靠延时/删断言取绿。

每项独立记录复现、根因、修改与验证，共用helper可批量改但不能整批假定已解决。区分“能找到”“属于当前对象”“动作正确”“结果及持久化正确”。准备不成立与应用不满足不能混为误接受；少量反例拒绝也不证明任意错误实现都会失败。

产品含义不明确时，先交ui按[需求同步方法](../bench-ui-curation/references/requirement-scenario-alignment.md)确认依据；不能从helper倒推标准。scenario文字同步不证明未执行能力被覆盖，保留独立缺口记录。

## 返回主流程

返回各需求/场景的闭合情况、反例与合理正例、实际调用及未覆盖分支。默认完成类型、素材契约及合成/状态模拟；仅用户已提供例程后进入主流程的应用迭代，不能默认扫描或启动应用。共享状态如需同库重复，不清历史取绿，不用历史对象替本test目标。

把静态怀疑、断言片段、完整评分用例、合成检查及应用结果分开报告；新约束揭露业务失败时保留失败，修复适配并不保证业务全通过。执行和证据按主流程的验证选择表，不因本skill被调用而重跑所有检查。
