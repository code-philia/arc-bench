# BookStack测试质量治理

## 范围与恢复

本阶段是任务6，复查现有测试的“前提—操作—断言”是否闭合。仅处理BookStack，固定Admin账号，不清数据库、不创建登录账号、不复用其他test生成的对象。现有24个spec/35个评分场景及需求身份保持；扩充本test准备数据以验证既有容量要求不等于新增评分场景。跨用户/跨对象新评分场景仍须另有指令。历史69处隔离内容已授权清理，当前0处；质量复查保持需求中的业务规则。仅整理skill时不重跑治理。

## 逐项审查

检查全部REQ及helper/fixture实际调用，不以函数存在或已导入证明断言生效。按需求/场景ID记录准备条件、刺激动作、应有结果、当前观测和遗漏，区分测试缺口与产品不满足。

| 问题 | 修复标准 |
| --- | --- |
| 元数据回填 | 创建保存后重开表单，编辑前检查原值，编辑保存后刷新重开检查新值，取消后检查原值；名称、描述、标签全部核对。保留标签顺序无关语义，不能忽略丢失标签或多余标签值。 |
| 容量 | 在当前test经UI准备超过上限的数据，检查真实可见记录数；本案例最近访问10、首页收藏4、最近更新5。仅检查一个新对象出现不能证明容量；标题、View All等不算记录，未知结构不能当0。 |
| 内容作用域 | 描述/正文绑定当前对象的详情/阅读区域，排除侧栏、导航、控件与编辑输入回显；精确输入值保持，不改成非空或整页包含。 |
| 登录耦合 | 登录helper只验证凭据提交和用户区域身份，提交按钮限定在登录表单；仪表盘可见性由对应REQ显式检查。不能因正文出现Admin认定已登录。 |
| 共享账号状态 | 随机业务身份、当前test父对象和明确初始状态；不要求列表最初为空。仅恢复本test改变的收藏，失败时也尝试恢复，保留原始错误和清理失败。历史排名仍可影响榜单，不声称新浏览器上下文能隔离服务端账号。 |
| 准备接口 | helper必须消费关联字段，或在任何UI副作用前明确拒绝。createPage当前拒绝chapterName；这解决静默错误，不代表章节页面准备已实现。 |

对需求已经明确但case不满足的业务结果保持失败，不通过删断言、补假数据、延长等待或改case使其变绿。新断言揭示的失败单独归因，不与适配回归混为一谈。

## 实施与验证

优先修共享helper/语义接口，再接入相关REQ；同步模拟归属检查以实际运行新增调用。容量准备可按实测增加该test超时，不普遍放宽断言等待。辅助计数兼容现有行/卡片/入口结构，需用超限正反例验证，不能只匹配方法调用次数。

按主skill验证选择表选取受影响检查，以下不是每次必跑清单：

```powershell
npm.cmd run check:bookstack
node curation_tool/check_bookstack_role_compatibility.mjs
node curation_tool/check_bookstack_preparation.mjs
```

适配脚本使用bench根目录的Playwright依赖，先核实依赖及Chromium可用性。扩展可复用检查验证真实helper，覆盖丢失字段、额外标签值、错误对象/侧栏同文、每个容量上限+1、未知计数结构、登录无仪表盘、收藏失败后恢复及保留历史状态、关联参数拒绝等。模拟归属不是浏览器业务验证。

有可用case时核实服务URL，运行关联REQ/全量；共享状态修复还应在同一数据库、不重置历史的条件下重复相关测试。分别记录独立通过范围、实际失败身份和触发位置；不要复用历史25/10或素材数量作为本次检查。无法保证任意历史排名时说明限制，不能改为接受历史对象代替本test目标。

需求文件、标记文本/次数及测试身份保持；检查新增断言确实接入。用state.py在quality阶段维护条目，verified绑定当前源指纹和实际通过范围，业务回归仍失败的相关条目保持blocked，其余独立推进。将最小证据、复查范围、残余共享状态和准备限制汇总到quality_governance及子进度，返回主skill收尾。按[产物约定](../bench-curation/references/state-and-artifacts.md)汇总后清理本轮报告，不永久堆积raw JSON和trace。
