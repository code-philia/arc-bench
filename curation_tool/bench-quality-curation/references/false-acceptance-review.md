# 错误实现误通过：审计与逐项约束修复

用于审查当前需求与现有评分测试是否对应，以及兼容适配是否放过错误对象、动作或结果。网页框架、是否显式使用role、容器标签本身不是业务正确性的判据；不以本参考自动新增评分场景或修改生成应用。

执行和证据门槛遵循[主流程](../../bench-curation/SKILL.md)。默认使用需求/图例/测试及独立模拟；下面few-shot不是预设存在的例程，只有用户提供/指定应用后才进入应用级迭代。

## 找到可被反驳的业务不变量

通读description、Given/When/Then、REQ和实际helper调用，为各需求记录：前提由谁创建、操作属于谁、输入是什么、结果在哪里观察、是否需要重开或刷新。沿所有替代定位路径检查；owner参数、语义接口名、已导入helper都不证明约束已生效。

| 易误接受的位置 | 最小错误实现 | 必须补足的证据 |
| --- | --- | --- |
| 操作作用域 | 子对象也有Actions/Delete；只剩错误对象的唯一入口 | 点击前确认用途及归属，范围内唯一；Actions/共同祖先/全页唯一不能代替owner。详见role子skill的[作用域few-shot](../../bench-role-curation/references/action-scope-compatibility.md)。 |
| 集合owner | 当前对象标题旁展示另一对象的唯一Pages | 所有具名及回退路径、实际条目都绑定正确父对象，不能跨子树补足。 |
| 正文/详情 | 列表caption冒作详情标题；另一对象或编辑器回显提供所需正文 | 当前对象确实进入详情/阅读状态，正文在正确内容边界，输入值精确。 |
| 容量 | 一部分是li、一部分是平铺卡片；只计一种结构 | 合并完整业务记录并去重表示，标题/维护按钮不算记录，未知非空结构不能按0。 |
| 交互能力 | tabindex惰性文字或无效果入口 | 可见、可聚焦、可激活和正确打开分别验证；要求键盘可用时实际操作并验证结果。 |
| 保存与取消 | 只存标题丢弃正文；编辑另建副本；点错对象但取消后原对象不变 | 回读同一份输入，检查可观察对象连续性；确认目标和结果都要对，持久化按需求验证。 |

优先构造业务上错误但表面足以满足当前断言的实现。仅加入同名重复目标不够，错误目标恰好唯一更容易被遗漏。对复杂布局可用合成DOM；需要验证保存和重开时用能表现错误状态转换的最小模拟，调用真实helper，而不是另写一套定位逻辑或只检查方法是否调用。

## 逐项修复闭环

1. **复现并限定结论**：记录需求/场景ID、helper、错误实现、仍被接受的断言、实际错误数据/副作用。区分静态怀疑、适配器片段复现、完整评分用例、真实应用结果。
2. **归因**：识别是适配路径丢失用途/owner、业务结果断言缺失、准备条件不成立，还是应用确实不满足需求。若产品含义尚未规定，使用[需求同步方法](../../bench-ui-curation/references/requirement-scenario-alignment.md)核实依据，不能为让样例通过而倒推产品标准。
3. **修复该约束**：优先改共享适配/helper，并核对评分REQ实际接入。补需要的结果断言；保留测试和需求身份、精确数据、已有业务规则。共用修复可一次覆盖多个REQ，每项仍有独立状态。
4. **双向验证**：错误实现必须被拒绝，正确的合理替代实现仍须通过。错误归属应在误操作前拒绝；正文丢失等结果错误在相应回读处失败。加入无main/无Actions标题/无显式role的可支持布局，防止修复又建立实现协议。
5. **回归与同步**：扩展独立适配检查；用户提供/指定例程后按影响跑相关REQ，共享路径广泛变化才扩大回归。同步description、scenario及实际测试动作。正常实现新失败时先核实DOM/状态/数据，不延时取绿，也不删新约束。
6. **逐项结案**：记录被拒反例、通过正例、实际命令、覆盖边界及剩余应用失败。独立项可继续，不能把所有项笼统标为已修。模拟通过不算应用通过；定向补测不与旧全量拼成新成绩。

现有类型/语义API、适配、准备归属脚本分别提供不同证据；通过数量不证明未覆盖错误不存在。材料及运行审计写ref/，共享skill只保存方法。

## Few-shot：错误实现与正确约束

### 1. 子页面删除后取消，书籍断言仍通过

**输入**：书籍A下页面P有自己的Actions/Delete。测试点了P的Delete再Cancel，最后检查A标题和描述不变。

**判定与修改**：这是误接受，取消后A未变不能证明入口属于A。在点击前约束所属对象，确认界面也核对目标。反例保留P的Actions，且将标题从h2替换为span；错误操作标志不能被触发。正例允许A和P的Delete共存。不能把所有页面强制改成某个role或操作区标题。

### 2. 六条记录却通过最多五条

**输入**：一条li记录加五条平铺入口，计数函数找到li就提前返回1。

**判定与修改**：适配计数漏项。合并这两种记录并去重记录内链接/按钮；混合五条通过、六条失败，附加Edit/View All等不能变成记录。不仅检查新目标出现，也验证完整容量。

### 3. Save Page只保留标题

**输入**：helper填写随机标题正文，保存后父列表出现该标题；实现实际丢弃正文。

**判定与修改**：创建准备成功不等于保存正确。重开本test页面读取正文，草稿重开编辑器核对回填；核对同一份精确输入，随后保持调用方需要的页面状态。合理标签变体通过、正文丢失失败；不能依赖另一test创建的页面替本次对象证明保存能力。

### 4. 真实应用失败，原因却是未规定的并列排序

**输入**：为验证最多四项，当前test收藏五个对象，它们访问数相同；测试要求最后创建的对象必在前四名。

**判定与修改**：先核实需求是否规定同分顺序。没有该规则时，不因helper挑了最后一个就补写排序要求。可从本test确实展示的对象身份中确定目标，再检查它唯一、列表容量和打开结果；不得选择历史对象或隐藏同一身份的重复入口。若历史排名可能排除全部本test对象，说明准备边界，不改为任意历史对象通过。
