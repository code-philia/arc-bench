# 元说明与重复治理

按[主流程](../bench-curation/SKILL.md)的范围和业务决定执行，验证、状态、暂存与交付清理统一由主流程管理。ui负责产品含义及一般性表述，data负责数据来源，quality负责覆盖和断言；本skill只整理语言及规则归属。

## 语义分类

通读description及Given/When/Then，结合父子上下文和真实调用记录原文、位置、处理及理由；不能只看关键词。

| 内容 | 处理 |
| --- | --- |
| evaluator、not tested、历史编辑及评测来源解释 | 移出产品需求，必要依据写本地记录 |
| unspecified、范围排除等说明 | 先核对是否承载真实验收边界；去解释不等于增加未规定的排序/格式承诺 |
| 依赖说明 | 保留自然登录/对象前提和合法引用，编排提示移到测试侧 |
| 父子重复规则 | 共性放合理父级，局部信息保留；合并前核对独有属性和实际消费方式 |
| 自然操作、UI创建、示例、归属、隔离和持久化 | 保留，不因像测试步骤或含具体值而删除 |

一般性与scenario含义对齐由ui的[同步方法](../bench-ui-curation/references/requirement-scenario-alignment.md)规定。不要重新裁定产品标准，也不要把用户明确的交互删掉；只移除评测/实现解释并整理重复。独立消费的子需求保留理解所需行为或合法引用，不能为去重删除Given/When/Then验收含义。

润色不应将混合业务段整段隔离或删除。过渡标记只在主流程允许时使用，不能把标记当完成，也不能因无例程保留本可清除的协议。

## 返回主流程

返回每项清理的前后业务含义、父子归属、独有字段是否保留及与测试的关系。只润色且业务未变时说明测试无需调整；一旦影响实际前提/操作/预期，转回ui/quality确认同步，不在清理阶段偷偷改标准。主流程负责解析、身份/引用核对及最终交付检查。
