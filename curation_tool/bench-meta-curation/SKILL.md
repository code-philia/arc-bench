# BookStack元说明与重复治理

## 入口和边界

仅处理BookStack任务3。当前交付版已获用户授权清理历史59处数据协议与10处元说明，共69处，当前0处；历史移除内容及范围边界在本地ref/bookstack/governance_reference.json的delivery中（如存在）。后续不重新加回旧标记。新工作若需暂存，必须说明过渡用途和清理条件，不把带评测协议的过渡稿当最终需求。固定时钟归任务4，精确UI约束归任务5，断言质量归任务6。创建或检查skill本身不触发治理。

## 分类和处理

通读全部description.text及场景Given/When/Then，结合父子上下文与相关tests/helper判断；关键词只作检索线索。按需求/场景/步骤ID和字段定位，记录原文、处理后文本、理由、保留的业务规则和测试关联。

| 内容 | 处理原则 |
| --- | --- |
| not sampled/tested、evaluator流程、来源保留或历史编辑解释 | 从产品需求中移除；必要的评测背景归档治理参考。尚未完成测试衔接时可按授权暂存，交付前清理。 |
| source does not define、unspecified、范围排除 | 先辨别是否限制验收范围；最终需求去掉解释性元说明，将未规定事项记录在治理参考，不把未规定的排序、期限或格式改成新业务保证。 |
| REQ依赖说明 | 业务上需要登录等条件自然表述；面向编排的提示移到评测侧；合法业务引用与场景对应保留。 |
| 父子复制的权限、容量、元数据定义和范围声明 | 将共性规则保留在合适父需求，直接删除子需求重复段；独有信息先迁移再删，避免削弱覆盖。 |
| 父需求概述、子需求具体行为、场景验收例子 | 属于合理层次表达，不机械去除语义重叠。 |
| UI创建、用户隔离、精确输入输出、持久化、父子归属、具体示例 | 属于自然操作或业务规则，不因像测试步骤而删除。 |

润色与隔离可改变措辞，但不能把整个混合业务句包进括号，或将业务要求变成可删除备注。暂存范围不包含相邻业务标点和条件。既有标记需按文本及出现次数核对，不能只比较总数。

父子去重前确认实际需求消费方式，检查相关测试和引用。保留每个REQ身份、可观察结果及必要前提；若子需求会独立消费，应保留理解所需的具体行为或合法父规则引用。不要删除Given/When/Then中的验收要求来追求更少重复。

## 验证和返回

改写前后核对需求/场景/步骤/图片ID、层级、引用和场景数量，实际解析YAML并检查引用可解析；同一图片ID可在多个需求中重复声明，但定义须一致。核对原标记文本和数量、新标记归属以及无双重包裹。与本轮无关的日期与时钟、产品文案和业务示例保持。

只润色说明和删除重复、业务行为与测试输入输出未变时，记录测试无需改动的理由，执行静态结构/引用检查和`git diff --check`即可。若影响真实前提、操作或预期，则同步对应测试，按主skill补类型/相关适配及可用case回归；不放宽断言，不自动修改验证case。历史25/10不是本轮或任务3的验证证据。

按主skill用`state.py record --phase meta ...`登记真实里程碑；命令格式见主skill。暂存改写可记录requirements_updated/tests_updated及实际检查，但有待确认移除的元说明时阶段保持partial，不标记最终complete。元说明隔离和重复去除分条记录，避免一项等待清理掩盖另一项已完成的范围。

将决定、标记归属/数量、验证范围及剩余项汇总到本地`ref/bookstack/governance_reference.json`的`meta_governance`及ref/中的本地进度，再返回主skill更新状态与收尾。本任务不新增永久报告；临时清单或前后文记录按主skill[状态和产物约定](../bench-curation/references/state-and-artifacts.md)汇总清理，不删除未归档的唯一证据。
